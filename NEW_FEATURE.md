# Новая функциональность: история рыночных цен

Дата: 01.11.2026  
Реализованный вариант: **3. История изменения рыночных цен**.

## 1. Выбор варианта и оценка затрат

| Вариант | Модели | Сервисы/логика | UI | Тесты | Сложность |
|---|---|---|---|---|---|
| 1. Watchlist и целевые уровни | 2 | проверка условий, дедупликация, уведомления | 3–4 страницы | 10+ | средняя/высокая |
| 2. Виртуальный портфель | 3 | операции, средняя цена, P&L, история | 4+ страницы | 12+ | высокая |
| 3. История рыночных цен | 1 | запись снимков, периоды, статистика, график | 1 страница + ссылка | 8–10 | **низкая** |
| 4. Симулятор стратегий | 2–3 | правила, автосделки, журнал, метрики | 4+ страницы | 15+ | очень высокая |

Выбран вариант 3, потому что он:

- переиспользует существующие Celery-задачу, сервис рыночных данных и plotly;
- не добавляет новых пользовательских сущностей и сложных бизнес-правил;
- даёт самостоятельную пользовательскую ценность и проверяемый результат;
- минимально влияет на текущую модель данных: одна новая таблица.

Фактический объём: 1 модель, 1 миграция, 1 сервис, 1 представление,
1 шаблон, изменения задачи и админки, 20 новых тестов.

## 2. Функциональные требования

| ID | Требование |
|---|---|
| FR-H01 | При каждом успешном получении последней цены система должна сохранять снимок: акцию, цену и время котировки. |
| FR-H02 | Повторный снимок с той же парой «акция + время котировки» не должен создавать дубль. |
| FR-H03 | Если внешний API не вернул время котировки, используется текущее время сервера. |
| FR-H04 | Ошибка сохранения снимка не должна прерывать обновление остальных акций и самой цены акции. |
| FR-H05 | Для акции должна быть доступна страница истории по `GET /history/<id>`; для несуществующей акции — 404. |
| FR-H06 | Пользователь должен выбирать период: 7, 30, 90, 180 или 365 дней. По умолчанию — 30 дней. Недопустимое значение заменяется значением по умолчанию. |
| FR-H07 | За выбранный период система должна показывать количество точек, первую, последнюю, минимальную и максимальную цену. |
| FR-H08 | Система должна рассчитывать абсолютное изменение цены и процентное изменение к первой цене периода. Если первая цена равна нулю, процент не рассчитывается. |
| FR-H09 | График должен строиться по накопленным в базе данным, а не по отдельному запросу в Tinkoff API. |
| FR-H10 | Для больших периодов график должен прореживаться (не более 500 точек) с сохранением первой и последней точки. |
| FR-H11 | На странице должен отображаться список 20 последних снимков выбранного периода. |
| FR-H12 | При отсутствии данных страница должна открываться и показывать понятное сообщение, а не ошибку. |
| FR-H13 | На странице акции должна быть ссылка на историю цен. |
| FR-H14 | Снимки должны быть доступны в админке Django с фильтрацией и поиском. |

Нефункциональные требования:

- не добавлять новых внешних зависимостей;
- сохранить обратную совместимость существующих страниц и API;
- не допускать дублей на уровне ограничения БД, а не только в коде;
- не выполнять тяжёлые запросы к Tinkoff API при открытии страницы истории.

## 3. Изменения архитектуры и данных

### Модель данных

Добавлена модель `dashboard.models.PriceHistory`:

| Поле | Тип | Назначение |
|---|---|---|
| `share` | FK → `Share`, `CASCADE` | акция |
| `price` | `DecimalField(20, 9)` | цена снимка без потери точности |
| `quoted_at` | `DateTimeField` | время котировки от API |
| `created_at` | `DateTimeField(auto_now_add)` | время записи в БД |

Ограничение `UniqueConstraint(share, quoted_at)` исключает дублирование
события на уровне базы. Миграция: `dashboard/migrations/0009_pricehistory.py`.

### Поток данных

```text
Celery beat (каждые 5 минут)
  -> update_last_price()
      -> get_last_data(share)        # Tinkoff API: price + quoted_at
      -> Share.save(...)             # текущая цена и тренд
      -> PriceHistory.get_or_create() # снимок без дублей
```

### Изменённые и новые файлы

- `dashboard/models.py` — модель `PriceHistory` и ограничение уникальности.
- `dashboard/migrations/0009_pricehistory.py` — миграция.
- `dashboard/tasks.py` — запись снимков, нормализация времени, изоляция ошибок.
- `dashboard/services/price_history.py` — периоды, выборка, статистика,
  прореживание и построение графика.
- `dashboard/views.py` — `ShareHistoryView`.
- `dashboard/urls.py` — маршрут `dashboard:history`.
- `dashboard/templates/dashboard/history.html` — страница истории.
- `dashboard/templates/dashboard/detail.html` — ссылка на историю.
- `dashboard/admin.py` — регистрация `PriceHistory`.
- `dashboard/tests_history.py` — 20 тестов новой функциональности.

### Пользовательский интерфейс

На странице акции появилась кнопка «История цен». Страница истории содержит:

- переключатель периода;
- карточки со статистикой;
- блок абсолютного и процентного изменения;
- интерактивный график plotly;
- таблицу последних снимков;
- сообщение при отсутствии накопленных данных.

Существующий график Tinkoff на странице акции сохранён без изменений и
по-прежнему показывает внешние дневные свечи; новый график строится только по
данным приложения.

## 4. Проверка

### Автоматические тесты

Добавлено 20 тестов:

- выбор и валидация периода;
- статистика, процентное изменение и деление на ноль;
- построение графика и пустой ряд;
- прореживание ряда с сохранением границ;
- уникальность снимка на уровне БД;
- страница истории, фильтр периода, пустое состояние, 404 и ссылка;
- запись снимка задачей, дедупликация, новая котировка, отсутствие времени.

Итог:

```text
python manage.py test        -> Ran 62 tests ... OK
python manage.py check       -> no issues
makemigrations --check       -> No changes detected
coverage report              -> 95%
ruff check .                 -> All checks passed
```

Регрессий в существующих 42 тестах нет.

### Проверка на реальном сервере

```text
GET /                         -> 200
GET /1                        -> 200
GET /history/1                -> 200
GET /history/1?days=7         -> 200
GET /history/1?days=365       -> 200
GET /history/9999             -> 404
```

Для локальной демонстрации в `db.sqlite3` созданы 1095 снимков (по 365 дней
для AAPL, AMZN и SBER). Количество точек по периодам: 7, 30, 90, 180 и 365
соответственно. База не входит в репозиторий.

Без `TINKOFF_TOKEN`:

- страница истории открывается и показывает пустое состояние;
- задача обновления цен не падает, а пропускает акции с предупреждением;
- снимки не создаются, пока нет реальных котировок.

## 5. Ограничения

- История начинает накапливаться только после запуска Celery с настроенным
  `TINKOFF_TOKEN`; ретроспективная загрузка свечей Tinkoff в эту таблицу не
  выполняется.
- Срок хранения снимков не ограничен; при необходимости очистку можно добавить
  отдельной периодической задачей.
- Отдельный REST-эндпоинт истории не добавлялся: функциональность доступна
  через веб-интерфейс и админку. Это сознательное ограничение минимального
  варианта.
