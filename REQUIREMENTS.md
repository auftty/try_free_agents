# Восстановленные функциональные требования

## 1. Аутентификация и управление пользователями

### ФТ-01. Регистрация нового пользователя
**Описание:** Система позволяет зарегистрировать нового пользователя по адресу электронной почты и паролю.
**Подтверждение в коде:** `user/views.py` — `RegistrationView`, `user/forms.py` — `RegistrationForm`
**Поведение:**
- Пользователь вводит email и пароль (дважды)
- Система проверяет совпадение паролей
- Система проверяет, что email не зарегистрирован
- Система создаёт пользователя и автоматически авторизует его
- После регистрации пользователь перенаправляется на главную страницу

### ФТ-02. Авторизация пользователя
**Описание:** Система позволяет авторизованному пользователю войти в приложение по email и паролю.
**Подтверждение в коде:** `user/views.py` — `AuthView`, `user/forms.py` — `AuthForm`
**Поведение:**
- Пользователь вводит email и пароль
- Система проверяет учётные данные через Django authentication
- При успешной проверке пользователь перенаправляется на главную страницу
- При ошибке отображается сообщение «Неверный логин или пароль»

### ФТ-03. Выход из системы
**Описание:** Система позволяет авторизованному пользователю завершить сеанс.
**Подтверждение в коде:** `user/views.py` — `LogoutView`
**Поведение:**
- При переходе по `/user/logout/` сеанс пользователя завершается
- Пользователь перенаправляется на главную страницу

---

## 2. Управление списком акций

### ФТ-04. Отображение списка акций
**Описание:** Система отображает таблицу всех зарегистрированных акций с пагинацией.
**Подтверждение в коде:** `dashboard/views.py` — `ShareListView`, `dashboard/templates/dashboard/list.html`
**Поведение:**
- Отображаются: тикер, название, ISIN, текущая цена, валюта
- Цена подсвечивается зелёным (рост) или красным (падение) в зависимости от `is_trend_high`
- Тикер является ссылкой на детальную страницу акции
- Пагинация по 100 записей
- Неавторизованные пользователи видят только список без кнопок управления

### ФТ-05. Просмотр деталей акции
**Описание:** Система отображает подробную информацию об акции с историческим графиком цен.
**Подтверждение в коде:** `dashboard/views.py` — `ShareDetailView`, `dashboard/services/graph.py`
**Поведение:**
- Отображается: наименование, текущая цена, валюта, время последнего обновления
- Отображается линейный график изменения цены за последние 180 дней
- График генерируется через Plotly на основе дневных свечей из Tinkoff API

### ФТ-06. Добавление акции
**Описание:** Система позволяет авторизованному пользователю добавить новую акцию.
**Подтверждение в коде:** `dashboard/views.py` — `ShareCreateView`, `dashboard/forms.py` — `ShareModelForm`
**Поведение:**
- Доступно только авторизованным пользователям (через `IsUserAuthenticatedMixin`)
- Отображается форма со всеми полями модели Share
- После сохранения пользователь перенаправляется на главную страницу

### ФТ-07. Редактирование акции
**Описание:** Система позволяет авторизованному пользователю редактировать данные акции.
**Подтверждение в коде:** `dashboard/views.py` — `ShareUpdateView`
**Поведение:**
- Доступно только авторизованным пользователям
- Отображается форма с предзаполненными данными
- После сохранения пользователь перенаправляется на главную страницу

### ФТ-08. Удаление акции
**Описание:** Система позволяет авторизованному пользователю удалить акцию из списка.
**Подтверждение в коде:** `dashboard/views.py` — `ShareDeleteView`
**Поведение:**
- Доступно только авторизованным пользователям
- Отображается страница подтверждения удаления
- После подтверждения акция удаляется, пользователь перенаправляется на главную

## 3. REST API

### ФТ-09. CRUD-операции через API
**Описание:** Система предоставляет REST API для управления акциями.
**Подтверждение в коде:** `dashboard/api/v1/views.py` — `ShareViewSet`, `dashboard/api/v1/router.py`
**Поведение:**
- `GET /api/v1/shares/` — получение списка акций с пагинацией
- `GET /api/v1/shares/{id}/` — получение деталей акции
- `POST /api/v1/shares/` — создание акции
- `PUT /api/v1/shares/{id}/` — обновление акции
- `DELETE /api/v1/shares/{id}/` — удаление акции

### ФТ-10. Фильтрация и поиск через API
**Описание:** Система поддерживает фильтрацию и поиск акций через API.
**Подтверждение в коде:** `dashboard/api/v1/views.py` — `ShareFilter`, `filter_backends`
**Поведение:**
- Фильтрация по `name` и `ticker`
- Поиск по полю `name`
- Сортировка по `name` и `ticker`

## 4. Автоматическое обновление данных

### ФТ-11. Загрузка списка акций из Tinkoff API
**Описание:** Система позволяет загрузить полный список доступных акций из Tinkoff Invest API.
**Подтверждение в коде:** `dashboard/management/commands/add_shares.py`
**Поведение:**
- Команда `python manage.py add_shares` запрашивает список через `client.instruments.shares()`
- Для каждой акции создаётся запись в БД (если ещё не существует) через `get_or_create`

### ФТ-12. Автоматическое обновление цен
**Описание:** Система автоматически обновляет текущую цену и направление тренда для всех акций.
**Подтверждение в коде:** `dashboard/tasks.py` — `update_last_price`, `config/celery.py` — beat-расписание
**Поведение:**
- Задача запускается каждые 10 секунд через Celery Beat
- Для каждой акции запрашивается последняя цена через `client.market_data.get_last_prices()`
- Обновляется `last_price` и `is_trend_high` (True если цена выросла, False если упала)

## 5. Выявленные дефекты и неоднозначности

### Дефект-01. Пустой токен Tinkoff API
**Файл:** `config/settings.py`, строка 134
**Описание:** Переменная `TINKOFF_TOKEN = ""` пустая, без реального токена API не будет работать ни загрузка акций, ни обновление цен, ни построение графиков.

### Дефект-02. Пустой SECRET_KEY
**Файл:** `config/settings.py`, строка 6
**Описание:** `SECRET_KEY = ""` — пустой ключ безопасности Django. Приложение может не запуститься или быть уязвимым.

### Дефект-03. Передача класса формы вместо экземпляра
**Файл:** `user/views.py`, строки 13, 41
**Описание:** В `AuthView.get()` и `RegistrationView.get()` в шаблон передаётся класс формы (`AuthForm` / `RegistrationForm`), а не экземпляр (`AuthForm()` / `RegistrationForm()`). Это может привести к некорректному рендерингу форм.

### Дефект-04. Небезопасное сравнение с None
**Файл:** `dashboard/tasks.py`, строка 16
**Описание:** Сравнение `share.last_price > last_price` при `share.last_price = None` вызовет `TypeError: '>' not supported between instances of 'NoneType' and 'float'`. Обработка ошибки есть (строки 20-22), но она маскирует проблему, а не решает её.

### Дефект-05. Отсутствие уникальности email на уровне БД
**Файл:** `user/forms.py`, строки 39-46
**Описание:** Проверка уникальности email реализована только на уровне формы (`User.objects.filter(email=email)`), но поле `email` в модели User не имеет ограничения `unique=True` на уровне базы данных. Это создаёт условие гонки при параллельной регистрации.

### Дефект-06. Неверное обращение к ошибкам валидации
**Файл:** `user/views.py`, строка 54
**Описание:** `form.errors["__all__"].data[0].message` — нестандартное обращение к ошибкам валидации Django Forms. Правильный способ: `form.errors.as_text()` или перебор `form.non_field_errors()`.

### Дефект-07. Устаревшие зависимости
**Описание:** Django 4.1.7 (выпущен в 2023), plotly 5.13.1, django-filter 22.1 — все зависимости устарели и могут содержать известные уязвимости.

### Дефект-08. Конфликт между комментарием и реальным расписанием Celery
**Файл:** `config/celery.py`, строка 13-14
**Описание:** В комментарии указано `"add-every-5-min"`, но реальный интервал — 10 секунд (`"schedule": 10.0`). Это вводит в заблуждение.

### Дефект-09. Неиспользуемый SQLite
**Файл:** `config/settings.py`, строки 92-95
**Описание:** Конфигурация PostgreSQL закомментирована, а SQLite раскомментирован в комментарии. В рабочем состоянии используется PostgreSQL, но файл `db.sqlite3` присутствует как артефакт.

### Дефект-10. Нет привязки акций к пользователям
**Описание:** Модель `Share` не содержит поля `user`, поэтому все акции являются общими для всех пользователей. В то же время CRUD-операции требуют авторизации. Возможно, это архитектурная ошибка — акции должны быть персональными.
