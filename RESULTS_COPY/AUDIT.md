## 2. Аудит зависимостей

Исходный стек 2023 года не запускается на Python 3.14: `Django 4.1` не
поддерживает эту версию, `psycopg2-binary` не собирается, а `protobuf 3.x/4.25`
падает на новых метаклассах Python.

| Компонент | Было | Стало | Причина |

| Python | не зафиксирован | 3.14.4 (совместимо с 3.12+) | актуальная версия интерпретатора |
| Django | 4.1.7 | 6.1.2 | поддержка Python 3.14, актуальные исправления безопасности |
| Django REST Framework | 3.14.0 | 3.18.3 | совместимость с Django 6.1 |
| django-filter | 22.1 | 26.2 | совместимость с Django 6.1 / DRF 3.18 |

## 3. Дефекты и решения

| ID | Дефект | Что сделано | Статус |
|---|---|---|---|
| D-01 | В API отсутствовало `uid`, Django подставлял пустую строку и второй `POST` падал на `unique` | `uid` сделан необязательным, при создании генерируется UUID, при обновлении сохраняется; добавлен `UniqueValidator` и тест на два создания подряд | исправлено |
| D-02 | `ShareDetailView.get` падал с 500 на несуществующем `pk` | `DetailView` возвращает штатный 404; добавлен тест | исправлено |
| D-03 | API был полностью открыт для записи | Добавлена настройка `API_REQUIRE_AUTH`: при `true` запись требует аутентификации. По умолчанию сохранено исходное поведение, чтобы не ломать существующих клиентов | устранено настройкой |
| D-04 | `ShareCreateView` не задавал `model` | Общие настройки вынесены в `ShareFormMixin` (`model`, `form_class`, `success_url`) | исправлено |
| D-05 | Имя задачи Beat не соответствовало интервалу (10 секунд) | Ключ `update-share-prices-every-5-minutes`, интервал 300 секунд | исправлено |
| D-06 | `QuerySet.update()` не обновлял `auto_now`-поле `updated_at` | Используется `save(update_fields=[...])`, включая `updated_at`; тест проверяет изменение времени | исправлено |
| D-07 | Из котировки брались только `units`, терялись `nano` и время | `quotation_to_decimal()` учитывает `units + nano / 10^9`; сервис возвращает время котировки, `updated_at` теперь обновляется | исправлено (время котировки не хранится отдельным полем — в модели его нет) |
| D-08 | Сравнение цены с `None` и общий `except` искажали тренд | Выделена `calculate_trend()`: `None` → рост, иначе сравнение `current >= previous`; тесты на все случаи | исправлено |
| D-09 | Вход обращался к `form.data["email"]` без валидации | Используется встроенный `LoginView` и `EmailAuthenticationForm` с валидацией e-mail | исправлено |
| D-10 | Ветка ошибки регистрации обращалась к `form.errors["__all__"]` | `FormView` + `RegistrationForm`; ошибки полей выводятся шаблоном, `KeyError` невозможен | исправлено |
| D-11 | `RegistrationForm.clean` обращался к `cleaned_data` без проверки | Используются `cleaned_data.get(...)` и проверки наличия значений | исправлено |
| D-12 | Уникальность e-mail проверялась с учётом регистра | Проверка `username/email` через `iexact`, нормализация e-mail к нижнему регистру при регистрации и входе; тест на `USER@example.com` | исправлено |
| D-13 | Пароли не проверялись настроенными валидаторами | Вызывается `validate_password()`; тест на отклонение слабого пароля | исправлено |
| D-14 | Выход выполнялся через GET без CSRF | Встроенный `LogoutView` принимает только POST; шаблон содержит POST-форму с `csrf_token`; тесты на GET 405 и POST 302 | исправлено (FR-19: метод намеренно изменён с GET на POST) |
| D-15 | При отсутствии входа редирект шёл на главную | `LoginRequiredMixin` + `LOGIN_URL = "user:auth"`: редирект на `/user/login/?next=...` | исправлено |
| D-16 | Ошибка Tinkoff API или пустой токен давали 500 на странице акции | `get_graph()` перехватывает ошибки и возвращает `None`; шаблон показывает понятное сообщение; тест | исправлено |
| D-17 | `add_shares` использовал `get_or_create` по всем полям и падал на дубле `figi` | `update_or_create(figi=...)`: существующая запись обновляется; тест на повторный импорт | исправлено |
| D-18 | Секреты, `DEBUG`, `ALLOWED_HOSTS`, БД и токен были зашиты в код | Настройки читаются из окружения/`.env`; в production без `DJANGO_SECRET_KEY` — `ImproperlyConfigured`; добавлен `.env.example` | исправлено |
| D-19 | `LANGUAGE_CODE = "en-us"`, `TIME_ZONE = "UTC"` при русском интерфейсе | `ru-ru`, `Europe/Moscow`; сообщения форм на русском | исправлено |

## 4. Выполненный рефакторинг

- `dashboard/services/market_data.py`: единая точка работы с Tinkoff SDK,
  ленивый импорт, `MarketDataError`, преобразование котировок и расчёт тренда.
- `dashboard/tasks.py`: тонкая задача с изоляцией ошибок по каждой акции,
  логированием и корректным обновлением полей.
- `dashboard/views.py`: переход на generic views, общий `ShareFormMixin`,
  `LoginRequiredMixin`, передача графика через `get_context_data`.
- `dashboard/services/graph.py`: построение графика через `Figure.to_html`,
  обработка отсутствия данных без исключений в HTTP-запросе.
- `dashboard/api/v1/`: явные импорты, `uid` в сериализаторе, стабильная
  сортировка и фильтры.
- `dashboard/management/commands/add_shares.py`: идемпотентный импорт по `figi`,
  отчёт о созданных/обновлённых/пропущенных записях.
- `user/`: регистрация на `FormView`, вход и выход на встроенных представлениях
  Django, формы с нормализацией e-mail и валидацией пароля.
- Шаблоны переведены на Bootstrap 5, добавлены вывод ошибок форм, POST-выход и
  резервное отображение графика.
- `config/settings.py`: конфигурация из окружения, SQLite по умолчанию,
  PostgreSQL через `DB_ENGINE=postgres`, безопасные production-настройки,
  Celery и логирование.
- Исправлена опечатка `DjangoOld` в `manage.py`; файл сделан исполняемым.
- Удалён wildcard-импорт в API-роутере, добавлен `pyproject.toml` с настройками
  `ruff`.

## 7. Осознанные ограничения

1. **Открытый API по умолчанию.** Исходное приложение разрешало анонимную
   запись через API. Чтобы не потерять совместимость, это поведение сохранено;
   для защищённого режима достаточно `API_REQUIRE_AUTH=true`.
2. **Выход только POST.** Это изменение метода относительно исходного GET
   (FR-19) сделано для устранения CSRF-уязвимости; интерфейс обновлён.
3. **Tinkoff SDK не входит в основной `requirements.txt`.** Пакет недоступен на
   PyPI; он устанавливается отдельно по инструкции из `README.md`. Без него
   приложение полностью запускается, а рыночные данные деградируют корректно.
4. **Нет владельца у акции.** Справочник общий для всех аутентифицированных
   пользователей; это соответствует исходной модели данных.
